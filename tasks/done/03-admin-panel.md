# 📋 Task: Admin Panel for User Management

## 1. Контекст / Зачем

Администратору нужен инструмент для управления пользователями: просмотр списка всех зарегистрированных пользователей, редактирование их данных и назначение прав администратора.

## 2. Цель

Реализовать админ-панель с полным CRUD-функционалом над пользователями, доступ к которой ограничен только пользователями с ролью администратора.

## 3. Acceptance criteria

- [ ] Первый зарегистрированный пользователь в системе автоматически получает статус `is_admin: true`.
- [ ] Маршрут `/admin` в приложении доступен только администраторам. Обычные пользователи при попытке доступа получают 403 Forbidden или перенаправляются.
- [ ] Реализована таблица пользователей с полями: email, дата создания (`created_at`), статус администратора (`is_admin`).
- [ ] Реализована форма редактирования пользователя: возможность изменить email, пароль и статус `is_admin`.
- [ ] В шапке приложения (AppHeader) появляется кнопка "Админ-панель", которая видна только пользователям с правами администратора.
- [ ] Запрещено снимать статус администратора с последнего админа в системе (вернуть 400 с сообщением).

## 4. Затрагиваемые файлы

### Backend (`apps/backend/`)

- `db.js`:
  - В функции `init()` добавить проверку и ALTER TABLE:
    ```javascript
    db.run("ALTER TABLE users ADD COLUMN is_admin BOOLEAN DEFAULT 0");
    ```
    (sql.js игнорирует ошибку если колонка уже существует)
- `server.js`:
  - Создание middleware `isAdmin` для проверки прав администратора.
  - Обновление `POST /api/auth/register`: логика назначения `is_admin = true` для самого первого пользователя в БД.
  - Новый endpoint `GET /api/admin/users`: список всех пользователей (защищен `isAdmin`).
  - Новый endpoint `GET /api/admin/users/:id`: данные конкретного пользователя (защищен `isAdmin`).
  - Новый endpoint `PUT /api/admin/users/:id`: обновление данных пользователя (защищен `isAdmin`).

### Frontend (`apps/frontend/`)

- `src/router/index.js`: Создание роута `/admin` и `/admin/user/:id` с навигационным гардом (`beforeEach`), проверяющим `isAdmin` в store.
- `src/views/AdminView.vue`: Новая страница со списком пользователей в виде таблицы.
- `src/views/AdminUserEdit.vue`: Новая страница для редактирования данных выбранного пользователя.
- `src/components/AppHeader.vue`: Добавление ссылки на админ-панель с условием `v-if="authStore.isAdmin"`.
- `src/stores/auth.js`: Добавление поля `isAdmin` в состояние пользователя после логина/регистрации.

## 4.1 Технические решения (приняты автоматически)

- [ ] **Валидация:** На бэкенде в `PUT /api/admin/users/:id` добавлена строгая валидация email (regex) и проверка на пустоту полей.
- [ ] **Безопасность:** При обновлении пароля через админку используется `bcrypt.hash` для обеспечения безопасности.
- [ ] **Безопасность:** Middleware `isAdmin` делает запрос в БД для проверки актуального статуса `is_admin`, чтобы изменения прав вступали в силу немедленно, не дожидаясь истечения срока JWT.
- [ ] **UX:** В формах редактирования добавлена блокировка кнопки "Сохранить" (disabled) во время выполнения API-запроса.
- [ ] **UX:** Реализовано подтверждение (window.confirm) перед изменением статуса администратора пользователя, чтобы избежать случайных ошибок.

## 5. План реализации

### Шаг 3: Обновление Auth Store и Роутинга

Добавить `isAdmin` в хранилище аутентификации на фронтенде и настроить защищенные маршруты в Vue Router.

### Шаг 4: Создание интерфейса админки

Реализовать `AdminView.vue` (список) и `AdminUserEdit.vue` (редактирование).

### Шаг 5: Интеграция в интерфейс

Добавить кнопку доступа к админ-панели в `AppHeader.vue`.

### Шаг 6: Обновление документации

## 6. Риски / Edge cases

- ️ **Удаление последнего админа:** Если единственный администратор будет лишен прав или удален, доступ к админке будет потерян. Решение: запретить изменение прав последнего администратора.
- ⚠️ **Конкурентная регистрация:** Если два пользователя регистрируются одновременно, оба могут стать админами. Решение: использование транзакций БД при проверке количества пользователей.
- ️ **XSS:** Ввод вредоносного кода в поле email. Решение: санитизация данных и валидация на бэкенде.
