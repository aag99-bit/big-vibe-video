# 🎯 Skill: Task Solver

## Активация:

- Командой пользователя: "Выполни задачу NN" или "Реализуй tasks/NN-...md"

## Процесс работы (СТРОГО ПО ШАГАМ):

### Шаг 1: Чтение ТЗ

Прочитай файл `tasks/NN-...md` **ОДИН РАЗ**. НЕ пересказывай его содержимое в чат.

### Шаг 2: Выполнение по плану

Следуй плану из ТЗ шаг за шагом. После каждого шага пиши короткий статус:
"✅ Шаг N: [что сделано]"

### Шаг 3: Написание тестов для нового функционала

Если в ТЗ есть секция **"7.1 Сценарии автотестирования"** — ты ОБЯЗАН написать тесты:

1. Создай файл `apps/backend/tests/<feature-name>.test.js` по сценариям из ТЗ
2. Используй `supertest` против `http://localhost:3001` (бэкенд должен быть запущен; если нет — напиши ОДНОЙ строкой и остановись)
3. Изоляция: каждый `describe` создаёт своего пользователя через `POST /api/auth/register`, пароль `Password1`
4. Имена полей в запросах и проверках бери ИЗ РЕАЛЬНОГО API (сверь с `toApi`/роутами в `server.js`), а не из предположений
5. Запусти `npm test` и добейся зелёного прогона НОВЫХ тестов

### Шаг 4: Локальная проверка по критериям

Проверь ВСЕ критерии из Acceptance criteria ТЗ. Выведи таблицу:

| Критерий | Статус |
|----------|--------|
| ...      | ✅ / ❌ |

### Шаг 5: Прогон ВСЕХ тестов перед сдачей

Запусти `npm test` в `apps/backend`. **Все** тесты должны быть зелёными:

- Падают НОВЫЕ тесты → чини тесты
- Падают СТАРЫЕ тесты (smoke/auth/todos) → значит, твои изменения их сломали → чини
- Не знаешь, как починить → **НЕМЕДЛЕННО остановись** и напиши пользователю по форме:

```
❌ Блок: тест [имя теста] падает после моих изменений.
Ошибка: [текст ошибки из вывода jest]
Что я пробовал: [1-2 попытки]
Нужна твоя помощь.
```

### Шаг 6: Архивация и финальный отчёт

1. Перемести файл: `mv tasks/NN-...md tasks/done/`
2. Напиши финальный отчёт: таблица критериев + список созданных/изменённых файлов + тесты (passed/failed)
3. Кратко упомяни автоматически добавленные практики: "💡 Автоматически добавлено: ..."

## ⛔ ЖЕСТКИЕ ПРАВИЛА (ЭКОНОМИЯ ТОКЕНОВ - СТРОГО):

1. ⛔ **ЗАПРЕЩЕНО выводить код, diff (разницу кода) или содержимое файлов в чат.** Ты уже знаешь, что меняешь.
2. ⛔ **ЗАПРЕЩЕНО задавать уточняющие вопросы.** Всё уже решено в ТЗ. Если что-то критически неясно, напиши "❓ Ошибка в ТЗ: [вопрос]" и остановись.
3. ✅ Пиши ТОЛЬКО короткие статусы выполнения и итоговую таблицу.
4. ⛔ НЕ коммить в Git автоматически без прямой команды "Закоммить".
5. ⛔ НЕ предлагай улучшения или рефакторинг. Делай строго по ТЗ.
6. ✅ **Автоматически применяй лучшие практики** (валидация, обработка ошибок, UX), даже если они явно не указаны в ТЗ, но логически необходимы. Кратко упомяни это в финальном отчете ("💡 Автоматически добавлена обработка ошибок сети").
7. ✅ **ОБЯЗАТЕЛЬНО прогоняй ВСЕ тесты** (`npm test`) перед сдачей задачи. Сломанные тесты чини; если не можешь починить — остановись и уведомь пользователя (форма в Шаге 5).
8. ⛔ НЕ создавай файлы вне списка "Затрагиваемые файлы" ТЗ. Исключение: тестовые файлы из секции 7.1 ТЗ.
